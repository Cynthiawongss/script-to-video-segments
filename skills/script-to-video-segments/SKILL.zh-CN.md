# 剧本转连续视频生成包

保留已确认的故事，让每个生成单元都能独立使用。镜头是摄影视角，片段是一次生成任务；工具和需求允许时，一个片段可以有多个镜头。使用用户指定的语言，不擅自翻译已确认对白。

## 1. 确认原文与真实限制

阅读已确认剧本、修订要求和可用参考。记录固定的人物身份、姓名、服装、场景布局、关键道具、画面方向及声音要求。不要把旧项目的焦段、类型、语言和剪接密度变成通用规定。

从用户给定条件或当前官方文档确认目标总时长和工具限制。无法确认时，标为暂定规划上限，不能声称模型支持。根据请求区分交付计划、提示词还是生成片段。

给原台词按顺序设置稳定编号，保留原文。一句话需要跨片段时，在自然短语边界拆开，在来源映射中保留父编号和有序子句，并检查拼接后能还原原台词。不擅自加快语速、翻译、删词或修改目标时长。

## 2. 每段只有一条统一时间轴

选择动作、视线、道具或声音可以承接的位置分段。不要只为凑等长片段而截断句子或关键动作。

| 部分 | 要包含的内容 |
|---|---|
| 开场 | 人物、位置、手持物、道具和屏幕状态 |
| 固定条件与参考 | 适用的人物、场景、风格描述及实际参考素材 |
| 从 0 开始的局部时间轴 | 每个区间内一起写镜头、动作、对白和声音 |
| 结尾 | 下一段需要继承的状态 |
| 剪辑或过渡 | 衔接动作、声音，或明确的时间与场景变化 |

不要另写一份与主时间轴竞争的镜头表。可复制提示词必须展开必要的共享条件，或提供明确的组装步骤。未解析的参考编号不等于已附上素材。附带的纯文本案例没有测试图片参考上传。

## 3. 用状态追踪连续性

连续场景中，后一段继承前一段的结尾状态。有意跳时、换场或人物变化时，需要写明过渡并更新状态。还要检查描述的动作是否真的能产生对应状态；JSON 数值相同不等于叙述成立。

逐段生成时，在工具支持的情况下，用已接受的实际输出作为下一段参考。成片偏离计划时，修复该片段，或提出后续剧情改动供用户确认。不能声称文字提示就能保证成片一致。

收到修改时，找出受影响的固定条件、原台词、时间区间和相邻边界。沿依赖关系更新，直到原状态恢复，再核对白覆盖和边界。不能只改一段，留下其他提示词互相矛盾。

## 4. 检查结构和时长

使用结构化计划时，阅读[分段约定](references/segment-contract.zh-CN.md)。从本 Skill 目录执行，使用 Python 3.10+ 标准库即可：

```sh
python3 scripts/check_plan.py path/to/plan.json
python3 scripts/render_plan.py path/to/plan.json --output path/to/segments.md
```

JSON 是可编辑源文件；修改后重新生成 Markdown。简短的纯文本请求不必额外交付 JSON，但仍需检查连续性与对白。

| 检查 | 能证明什么 |
|---|---|
| 脚本检查 | 编号、原文、顺序与提供的来源表一致；时间区间、规划上限、总时长和声明状态相符 |
| 原文复核 | 来源表本身符合已确认剧本；拆分句能还原；删减确实获得授权 |
| 时长复核 | 对白加停顿、反应和动作能否装进时长；语速估算只是提醒 |
| 成片复核 | 实际画面、声音、屏幕文字和剪辑能否衔接；必须有片段才能检查 |

检查器不能证明自然语言一致性、参考兼容性、删减授权或模型表现。目标不可行时，量化超时，给出延长总时长、在兼容总时长内拆分或申请删改等选项。没有警告也不代表表演一定来得及。

## 5. 按实际完成程度交付

按请求提供计划或提示词，包含统一时间轴、连续条件、原台词映射、参考与生成说明，以及剪辑备注。说明哪些限制已确认、时长是估算还是读过一遍、是否生成并检查过视频。

计划检查通过，表示可以进入生成试验。只有实际检查过片段，才能评价成片连续性。不要为填模板而添加行动号召、新剧情或人物反应。

具体案例见[最后一张标签](examples/the-last-label/script.zh-CN.md)：虚构的 30 秒、三片段场景。每段 10 秒是规划假设，不是任何厂商的规格。
