# 视频分段计划约定 v1

JSON 是可编辑源文件，`render_plan.py` 从中生成 Markdown。检查器不会生成视频或访问网络。

## 根字段

| 字段 | 含义 |
|---|---|
| `schema_version` | 固定为 1 |
| `title` | 场景名 |
| `planning` | `target_seconds`、`max_segment_seconds`、`limit_basis`、`speech_unit`、`max_units_per_second` |
| `locks` | 非空映射：稳定编号对应实际人物、场景或风格描述 |
| `source_dialogue` | 按原顺序排列的 `{id, speaker, text}` |
| `omissions` | `{id, authorization}` 列表；未经批准删减时为空 |
| `segments` | 有序片段列表 |

`limit_basis` 说明限制来源或暂定性质。`speech_unit` 支持 `whitespace_words` 和 `cjk_characters`；后者实际只是非空白字符计数，混合语言、标点等需人工复核。语速阈值不是实测结果。

原句跨片段时，先在来源表中拆成有序子句编号，并在原文说明里保留父编号、原句和拼接关系。检查器只比较给定来源表，不会自动检查它与原始剧本的对应关系。`authorization` 填了文字只是记录，不构成真实授权证明。

## 每个片段

包含 `id`、`duration`、`lock_ids`、`opening_state`、`closing_state`、`beats`、`bridge`。

开场和结尾状态是非空映射，整个序列使用同一组键，例如位置、人物位置、道具状态和屏幕状态。把可追踪状态与风格描述分开。连续动作时 `bridge` 为空；边界变化时说明具体原因，例如标注“次日”的转场。

当前 v1 格式要求每段包含全部根级固定条件编号；对不在镜头中的人物说明其缺席状态。根级条件只保留本序列需要的内容。更复杂的逐镜头参考资产管理不包含在这个文本检查器中。

每个时间区间包含 `start`、`end`、`camera`、`action`、`audio`、`dialogue`、`state_in`、`state_out`。区间状态使用与片段相同的键，从开场连续接到结尾。`dialogue` 是原台词对象列表；无对白时为 `[]`。

时间连续覆盖 `[0, duration]`，不重叠、不留空档。原台词按来源顺序出现一次，经过批准删减的除外。各片段时长之和等于目标总时长。需要改总时长时，同时更新目标和需求记录，不能隐藏差异。

## 检查器以外的复核

脚本核对结构、时间计算、对白及声明状态，提示超过给定阈值的语速估算。它不能看参考图片、判断“拿起杯子”是否与“杯子在桌上”冲突、证明删减授权、判断表演，或保证画面、声音和口型一致。

修改时，先改共享固定条件，再改相关区间，然后沿后续开场和结尾状态继续更新，直到原状态恢复。重新生成提示词，并通过原文复核、试读或生成试验检查语义和时长。
